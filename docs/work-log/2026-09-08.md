# 2026-09-08 작업 기록

## 결과

n8n이 Neo4j에 적재한 실제 GBIF 관찰을 FastAPI에서 구조화 조회하는 경로를
구현했다. `serve-neo4j`는 기존 fixture 답변·문헌 검색과 함께
`GET /v1/observations`를 제공한다.

## 구현

- `OperationalObservationQuery`와 taxon/place/citation/observation 읽기 모델 추가
- `Neo4jOperationalObservationRepository`의 고정 parameterized Cypher 구현
- taxon key, 학명·원본 일반명, 장소, 관찰일 범위, limit/offset 필터 추가
- GBIF provider, 허용 dataset·license와 완전한 provenance 경로를 요구하는
  fail-closed 조회 적용
- 일반화된 관찰의 위도·경도·좌표 불확실성을 API 경계에서 비공개 처리
- `mode: operational`, `data_source: gbif`, `fixture_only: false`와 원본·dataset·
  EvidenceUnit·license URI·허용 media metadata를 포함하는 응답 계약 추가
- fixture 모드와 운영 backend 장애에서는 HTTP 503 반환

## 검증 경계

단위·API 계약 테스트에 더해 실제 `dove-graph` Neo4j 2026.07.1 연결을 확인했다.
fixture는 Taxon 10, Observation 100, Document 2, Chunk 4이며 비공개 좌표와 제한
관찰은 0이었다. 신규 운영 repository로 관찰 19건과 허용 media 11건을 읽었고,
19건 모두 `generalized`라 위도·경도·좌표 불확실성이 숨겨졌다.

n8n 수동 실행 `17374`로 실제 GBIF API의 2026-08-09~2026-09-08 데이터를
조회하고 community Neo4j node까지 end-to-end 검증했다. source 19, observation 19,
taxon 39, taxon link 38, media 11, quarantine 0을 적재했고 검증·cursor 갱신 노드·Discord
성공 알림 단계가 모두 실행됐다. 수동 실행에서는 `Advance n8n cursor` 노드가
실행되어도 workflow static data가 저장되지 않아 배포 workflow의 cursor는 기존
2026-09-07(`n8n-17246`)을 유지한다. Neo4j `IngestState`는
`gbif-live-2026-09-08`, `n8n-17374`를 가리킨다. 테스트를 위해 임시로 넓힌 30일
조회 범위는 실행 직후 원래 cursor 기반 증분 설정으로 복구했고 workflow는 비활성
상태를 유지했다.

반복 적재 뒤 하나의 관찰에 여러 source snapshot과 dataset license가 연결되어 API가
19건을 38행으로 반환하는 문제도 발견했다. 조회 쿼리가 관찰별 최신 provenance를
선택하고 license를 집계하도록 수정했다. TestClient의
`GET /v1/observations?limit=100`은 최종적으로 HTTP 200, 고유 관찰 19건, 허용 media
11건, `mode: operational`, `fixture_only: false`를 반환했다.
DB 없는 전체 suite는 134개 중 113개 통과, Neo4j opt-in 21개 skip, 실패 0이며
기존 gold 질문은 15/15를 유지했다.

운영 관찰은 아직 `/v1/answers`의 자연어 답변이나 `/v1/search`의 문헌 임베딩
검색에 합쳐지지 않는다. 다음 단계는 n8n workflow 활성화 여부를 결정하고, 그 뒤
운영 관찰을 사용하는 근거 기반 답변 경계를 설계하는 것이다.

## 분류·형질 기준정보 수집 추가

종별 특징과 분류학 정보를 확장하기 위한 source registry와 collection point를 만들고, 승인된 세 포인트를 별도 n8n 기준정보 workflow에 연결했다. 기존 GBIF 관찰 workflow는 그대로 유지한다.

## 결정

- Claude 분류학 제안은 73/100, GPT-5.6 Terra claim-first 제안은 93/100으로 평가했다.
- 전체 데이터 모델은 `terra-claim-first`를 선택하고, 기준 분류체계는 Claude 제안의 AviList, 동의어·crosswalk 보조는 Catalogue of Life/ChecklistBank를 사용한다.
- AviList v2025b와 EltonTraits 1.0은 직접 파일 URL과 SHA-256을 고정했다.
- ChecklistBank는 2026-08-20 release(dataset 316115, DOI `10.48580/dgywk`)를 고정했다.
- 라이선스가 `review_required` 또는 `restricted`인 AVONET, NIBR, EcoBank, IUCN, GBIF name match는 자동 수집에서 제외했다.

## n8n 연결

`n8n/robingraph-reference-ingest.json`은 n8n 기본 HTTP, Crypto, Extract From File, Code, Merge 노드와 Neo4j community node를 사용한다.

- AviList 33,684개 taxonomy row와 33,638개 계층 link를 적재한다.
- EltonTraits 원본 9,995행 중 identity가 있는 9,993행을 처리한다.
- AviList species와 exact unique match되는 7,752개 프로필에서 46,512개 `TraitClaim`을 만든다.
- 미대응 2,241개는 ChecklistBank 검토 URL이 있는 `TaxonMappingCandidate`로 남긴다.
- taxonomy 1,000행, trait claim 2,000개, candidate 1,000개 단위로 적재하고 모든 반환 count를 검증한다.
- 중간 batch가 실패하면 active taxonomy/trait release를 갱신하지 않는다.
- 기존 GBIF 외부 분류 개념도 학명과 rank가 정확히 일치할 때만 AviList로 향하는 mapping claim 후보를 만든다.

## 검증

- 두 실제 snapshot으로 normalization과 claim 생성을 오프라인 실행해 고정 count와 77.6% exact match 비율을 확인했다.
- 모든 n8n Code node와 Neo4j Cypher expression의 JavaScript 문법 검사를 통과했다.
- workflow import shape, 연결, source allowlist, hash node, batch gate, fail-closed 경로, credential mapping 테스트를 통과했다.
- NAS n8n API URL/key가 현재 작업공간에 없어 원격 workflow 생성과 Manual Trigger 검증은 아직 하지 않았다.

상세 절차는 [분류·형질 기준정보 수집 런북](../n8n/reference-ingest.md)을 따른다.
