- 두 workflow를 구분하는 `--workflow reference|avonet` 배포 옵션과 각각의

- AviList 결측 Sequence를 문자열 ID로 잘못 저장하는 문제를 수정했다.
- EltonTraits 음수/0 체중, 비유한 숫자, boolean·분포 범위·중복 ID를 검사한다.
  원본 먹이활동 분포 합계가 99인 381개 프로필은 ±1 허용 범위 안에서 경고를
  보존하며 정규화하지 않는다. 미매핑 프로필도 후보에 JSON으로 보존한다.

## 메모리 문제와 재개 지점

AviList Explorer 공식 JSON은 Extended XLSX와 사용하는 데이터가 같고 HTTP Range
요청도 지원한다. 하지만 33,684행을 n8n item으로 한 번에 확장하거나 단일 item에서
전체 `JSON.parse`를 수행하는 방식은 모두 n8n을 재시작시켰다. 따라서 reference
정식 workflow는 활성화하지 않았다. 재개할 때는 byte-range 기반 단계별 수집과
parameterized Neo4j Query API 적재로 정식 workflow를 바꾼 뒤 활성화해야 한다.

AVONET 실제 Neo4j 적재는 실행하지 않았다. 원본 XLSX에 큰 개체자료 시트가 있어
n8n workbook 전체 파싱의 메모리 문제를 먼저 해결해야 한다. 현재 변환 검증 결과는
11,009종, 원본 형질값 143,004개, 적재 대상 claim 128,331개, 후보 1,130개다.
