# [RG-212 후속] 고정된 TEST 앱의 신규 36문항·12질문군 평가 — 2026-10-26

## 요약

사용자의 “계속 테스트” 요청에 따라 10월 24일 TEST 앱을 변경하지 않고 개발에 사용하지 않은 새 질문군으로 평가했다. 신규 36문항 중 23개가 판정 기준을 통과하고 13개가 실패했으며, 질문군은 12개 중 4개 통과·8개 실패였다. 실제 종 답변은 11건으로, 23개 판정 통과 전체를 답변 성공으로 해석하지 않는다.

이전 24문항·8개 군의 최종 통과는 실패를 보고 수정한 피드백 노출 회귀였다. 이번 최초 실측과 합치지 않았고, API 결과를 본 뒤 앱·gold·평가 알고리즘을 수정하거나 재호출해 통과로 바꾸지 않았다. 결과와 원본 응답을 MLflow에 저장하고 재조회했다. RG-212는 진행 중이며 앱 수정·새 배포·운영 반영은 하지 않았다.

## 1. 작업 배경 및 문제 분석

10월 24일 최초 봉인 18문항은 16/18·4/6군이었고, 이후 피드백 노출 회귀에서 24/24·8/8군을 확인했다. 최종 24개는 답변 19건과 자료 부족·검색 결과 없음·지원 불가·부정 보류 5건이었다. 그 결과만으로 새로운 질문에도 같은 성능이 유지된다고 판단할 수 없어 새 자료로 평가했다.

이번에는 기존 앱을 고정한 상태에서 동치 문항의 조건 보존과 대조 문항의 차이를 함께 검사했다. HTTP 200이나 trace 처리 성공만으로 의미 해석·실제 실행의 성공을 판단하지 않았다. 같은 요청의 실행 계획, 조건, 응답 분류를 함께 확인했다.

## 2. 평가 설계 및 동결

```text
앱 소스·runtime 동결 → 독립 gold 검토 → 자료 동결
→ 최초 실제 요청 36개 → 응답·trace 보존 → 엄격 개별·질문군 판정
```

- 앱 동결 시각은 `2026-10-26T04:31:23.247453+00:00`, 자료 동결은 `2026-10-26T04:37:37.246111+00:00`다. 구현 담당은 앱 동결 전에 질문을 읽지 않았다.
- 새 자료는 12개 질문군·36문항이며 각 군은 동치 질문 2개와 대조 질문 1개로 구성했다. 동치 두 개가 각각 통과하고 실제 계획도 같아야 하며, 대조 문항은 별도 조건·범위 또는 보류 기준을 만족해야 질문군이 통과한다.
- 모델이 작성한 gold를 별도 에이전트가 36문항 정적으로 검토했다. 사람 검토는 아니다. 실측 전 모호한 표현 한 문장을 정리했지만 예상 조건은 변경하지 않았다.
- 자료 SHA256은 `77881c3c6405d082a10796bb076c6a98a67ed6dc859b35d5b22aa185a83660a6`다. 동결 전 실제 API 실행은 없었다.
- 지원 답변·자료 부족·검색 결과 0건·정당한 보류·false hold·잘못된 실행을 구분했다. 종·아종 자료나 분류 범위를 임의 대체하지 않았다.
- API 결과 이후 gold와 평가 알고리즘 변경, 추가 API 호출, 앱 보완 후 재검증은 없었다. 이번 결과는 최초 실측 그대로다.

## 3. 주요 작업 및 자료

### 파일 및 변경 범위

- `data/eval/graph_questions/question-families-v2/holdout.json` — 동결한 신규 36문항. 같은 폴더의 manifest·validation에 구성과 사전 확인을 기록했다.
- `scripts/evaluate_graph_question_families.py` — 평가기 보완. 알려지지 않은 보류 분류를 통과시키지 않고, 전종 범위를 평가할 때 명시적인 `taxon: null`, 유효한 coverage, 같은 요청의 canonical plan을 요구한다.
- 평가기 관련 회귀 검사 — synthetic 11건 통과·0 실패·0 skip. 판정 로직 검사이며 실제 모델 응답 정확도와 별도다.
- `docs/verification/assets/2026-10-26-fresh-question-families/` — 동결·사전 검토·원본 응답·trace·점수·독립 재채점·MLflow 저장 영수증. `summary.json`, `failure-analysis.json`, `runtime-final.json`에 최종 결과·원인·환경을 정리했다.
- `docs/work-log/2026-10-26-fresh-question-family-validation.md` — 저장소 상세 기록 경로.

### 평가기 변경 전후

이전 평가기는 예상하지 않은 보류 분류를 충분히 엄격하게 거부하지 못했고, 특정 분류군이 없는 전종 조회를 일반 taxon 필수 검사와 구분해야 했다. 이번에는 미등록 분류를 실패로 처리하고, 전종 조회임을 명시하는 응답 및 같은 요청의 계획 근거가 있어야 통과하도록 보완했다. 기대값만 보고 실행 범위를 추정하지 않는다.

기존 v1 저장 응답을 보완된 평가기로 다시 채점한 결과는 24/24·8/8군이었다. 이것은 저장된 자료 재채점이며 실제 API를 다시 실행한 결과가 아니다. 실제 결과가 나온 뒤 이번 점수를 올리려고 평가 기준을 바꾸지 않았다.

앱 코드·설정·이미지는 수정하지 않았다. graphify 갱신은 평가기 변경 후 수행됐으나 독립 기록에 따르면 별도 raw 로그는 보존되지 않았고 SQL parser 의존성 경고가 있었다. 첫 실측 뒤 그래프 갱신을 다시 실행하지 않았다.

위는 이번 측정에서 확인한 원인 분류와 다음 작업의 우선순위다. 해당 앱 수정을 완료했다는 기록이 아니다. 공통 원인별 보완 뒤에는 이번 문항을 피드백 노출 회귀로 다루고 별도 새 문항으로 일반화를 확인해야 한다.

### 독립 재채점·MLflow

`independent-signoff.json`은 저장된 응답·trace만 재채점해 동일한 23/36·4/12군을 확인했다. 36개 모두 HTTP 200, 고유 trace ID 36개, span ID 233개였고 질문은 동결 자료와 일치했다. API 응답 disposition과 trace tag도 일치했다. 모델·서버 응답 모의는 없었다.

연결 검증은 runner의 질문 일치·고유 질문/trace/span ID·응답 분류 일치에 근거한다. 보존한 진단 spans에는 HTTP root span이 빠져 있다는 한계를 남긴다. 독립 검토자는 새 API·DB 요청을 하지 않았다.

기존 실험 33의 [신규 질문군 평가 run](https://mlflow.dove-nest.com/#/experiments/33/runs/26d2af39b5c64fe08ccb88e95ed0e7aa)은 FINISHED이며, dataset·동결 정보·점수·같은 요청 응답·평가기 artifacts를 저장 후 재조회했다. 이전 trace를 삭제하지 않았다.

앱 수정이 없는 평가이므로 전체 앱 단위 시험·브라우저·물리 모바일 시험을 오늘 다시 실행했다고 주장하지 않는다. 과거 단위 시험의 통과 수치를 이번 실행 결과에 포함하지 않았다.
