# 문서 담당 에이전트 추가 및 공통 지침 전파

## 배경과 목표

사용자가 문서 작성용 에이전트를 생성한 뒤 AGENTS.md 수정과 반영을 요청했다. 기존 Codex·Claude·UI Antigravity 역할에 별도 문서 담당을 추가하고 네 워크트리에 동일한 공통 역할 지침을 적용했다.

## 확인 근거와 변경 전후

Orca 워크트리·터미널 조회 및 각 AGENTS.md를 확인했다. 새 에이전트는 main-2 워크트리의 브랜치 dev에서 실행 중인 Antigravity이며, UI 담당은 main 워크트리의 브랜치 dev-agy다. 제품명이 같아도 워크트리와 역할로 구별한다. 새 워크트리에는 기존 세 역할 섹션이 없었다.

변경 전 Codex가 통합·TEST 검증과 문서 정합성을 함께 맡았고 공통 지침의 전파 대상은 두 자식이었다. 변경 후 문서 담당이 상세 작업 기록, 요청된 관련 문서, Obsidian 작업 기록과 백로그 정리를 맡는다. Codex는 구현·검증 증거를 전달하고 기술적 정확성을 최종 확인한다. Claude와 UI 담당은 실행 결과와 미검증 범위를 Codex에게 전달한다.

## 변경 파일과 구현

다음 네 AGENTS.md의 공통 역할 섹션을 일치시켰다.

- dev-codex/AGENTS.md: 문서 담당 역할과 전달 절차 추가, 세 담당 에이전트와 네 워크트리 기준으로 수정.
- dev-claude/AGENTS.md: 같은 공통 역할 섹션 반영.
- main/AGENTS.md: UI 담당 역할을 유지하면서 같은 공통 역할 섹션 반영.
- main-2/AGENTS.md: 기존 graphify·상세 문서 기준·운영 배포 승인 지침을 유지하면서 공통 역할 섹션 추가.

최초 현황 점검 지시는 과거 이력임을 명시했다. 최초 그래프 부재 기록도 당시 관찰임을 명시하여 현재 상태로 오해하지 않도록 했다. 문서 담당은 자기 워크트리 문서만 수정하고 Codex가 검토 후 통합하며, 같은 작업의 Obsidian은 담당자 한 명이 수정하도록 했다. 미확인 성공·배포·커밋·동기화 완료를 기록하지 않는 기준을 추가했다.

## 실제 검증과 전달 결과

- Python 비교: 네 파일의 공통 역할 섹션이 동일함을 assertion으로 확인했다. SHA-256은 `169218ad46b12e52857f6689084f5bdd0bf47b5f56e636f3b133ad0183b96263`이다.
- 각 파일의 공통 역할 섹션 앞 기존 지침 보존을 assertion으로 확인했다.
- `git diff --check -- AGENTS.md`: 네 워크트리 모두 통과했다.
- Orca terminal send로 Claude, UI 담당, 문서 담당의 기존 세 터미널에 자기 AGENTS.md 읽기와 역할 확인을 요청했다. 세 입력 모두 accepted였고, Claude는 turn_started도 관측했다. 두 Antigravity 제공자는 제출 관측 미지원이므로 이후 터미널에 실제 요청 표시를 확인했다. 입력 수락과 지침 숙지 완료는 구분한다.
- 앱 코드 변경이 없는 문서·지침 작업이므로 단위 테스트, 실제 DB/API 검사, 브라우저 검증은 실행하지 않았다. fixture 검증도 수행하지 않았다.

## 배포·커밋 및 한계

이번 작업으로 서비스 재시작, TEST/Production 배포, DB 변경, commit/push/병합은 수행하지 않았다. 기존 미커밋 앱 변경은 유지했다. Obsidian 문서·백로그는 이번 지침 반영만으로 변경하지 않았다. 향후 실제 작업 기록을 맡길 때 문서 담당에게 증거와 대상 경로를 함께 전달하고 동기화 결과를 별도로 확인한다. 에이전트별 숙지 응답은 아래 추가 확인에 실제 관측된 결과만 기록한다.

## 추가 확인: 실제 숙지 응답

Orca terminal read로 세 담당자의 실제 응답을 확인했다. Claude는 갱신된 AGENTS.md를 읽고 검색·API 담당 범위와 Codex를 통한 증거 전달을 확인했다. UI 담당은 UI·접근성 범위와 문서 담당에게 중앙 기록을 이관하는 절차를 확인했다. 새 문서 담당은 main-2/브랜치 dev 역할, 근거 기반 상세 기록, 자기 워크트리 문서만 수정, Codex 검토 후 통합 경계를 확인하고 대기한다고 응답했다. 따라서 세 터미널 모두 단순 입력 수락을 넘어 지침 숙지 응답까지 확인했다.
