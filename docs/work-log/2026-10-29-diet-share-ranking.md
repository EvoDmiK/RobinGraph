## 1. 작업 배경 및 문제 분석

기존 그래프 질의 결과는 이름 정렬 뒤 20건 제한이 적용되어, 조건에 맞는 먹이 비율이 큰 종이 표시 목록 밖으로 밀릴 수 있었다. 단순히 반환된 20건만 다시 정렬하면 누락된 높은 비율의 종을 되살릴 수 없으므로 제한 이전의 전체 조건 일치 행을 기준으로 정렬해야 한다.

이번 순서는 먹이 조건에 따른 표시 우선순위다. 새 조류 사실·먹이 비율이나 자료 없는 값을 생성하는 작업이 아니다. 기존 원자료 성분을 여러 조건에서 가리키는 경우 합산 중복을 막아야 한다.

## 2. 해결 방안 및 설계

먹이 비율 조건에 한해 전체 일치 행을 가져온 뒤 원자료 JSON을 안전하게 파싱하고, 선택된 먹이 조건에 대응하는 성분의 합집합으로 합산한다. 합산 비율 내림차순, 기존 이름 동점 순서로 정렬한 뒤 20건을 적용한다. 여러 조건의 원문 언급 순서는 점수 우선순위가 아니다.

```text
조건 일치 전체 행
→ 원자료 JSON 안전 파싱
→ 조건별 원자료 성분 union
→ 해당 성분 비율 합산 DESC + 기존 이름 동점 순서
→ 최대 20건
```

전체 일치 행을 처리하는 비용을 기존 방식과 비교 측정했다. 전체 범위의 전송량과 처리 시간 증가는 아래에 공개하며 성능 개선으로 설명하지 않는다.

### 실제 DB 읽기 전용 성능 비교

원본과 후보 코드를 각각 같은 조건으로 3회 측정했다. mock이 아닌 실제 TEST DB 조회이며, `application_ms`는 backend 처리 계측이다. 전체 공개 HTTP 질의 분류·응답 시간을 뜻하지 않는다. tracemalloc 사용 비용이 포함되며 반복 0을 제외한 반복 1·2를 warm 표본으로 구분했다.

| 대상 | 일치 수 | 기존 반환 행 / 직렬화 크기 | 후보 반환 행 / 직렬화 크기 | 기존 warm 처리 | 후보 warm 처리 |
| --- | ---: | --- | --- | --- | --- |
| 전체 열매 조건 | 2,551 | 21행 / 16,407 bytes | 2,551행 / 1,966,259 bytes | 286.4~323.5ms | 1,174.6~1,188.7ms |
| 까마귀과 열매 조건 | 76 | 21행 / 22,129 bytes | 76행 / 79,641 bytes | 121.2~121.9ms | 126.3~134.0ms |

전체 열매 후보의 warm Python peak는 약 16.9MB였다. 첫 반복은 기존 362.8ms·후보 1,781.7ms, 까마귀과는 기존 137.5ms·후보 440.7ms였다. 이 표본에서 넓은 범위는 전송·파싱 행 수 증가에 따라 비용이 분명히 늘었다. 동시 부하·장시간 처리·운영 성능을 측정한 결과가 아니며 작은 표본 평균을 일반 성능 보장으로 쓰지 않는다.

두 방식 모두 최종 목록은 20건이며 일치 수는 같았다. 전체 열매 기존 상위 3개는 `Polyboroides typus`, `Turdus feae`, `Pluvialis fulva`; 후보는 `Treron sieboldii`, `Ara militaris`, `Anodorhynchus hyacinthinus`로 바뀌었다. 최종 비율·순서 정확성은 아래 배포 후 독립 비교와 공개 응답 검증으로 확인했다.

근거: `performance-before-backend.json`, `performance-candidate-backend.json`. 전체 HTTP 분류를 포함한 별도 배포 전 3질문 기준선은 `baseline-public-api.json`이며 위 DB 처리 시간과 혼합하지 않는다.

### 실제 배포 후 검증

최종 배포된 코드와 실제 TEST DB의 후보 전체를 독립적으로 계산해 top 20과 비교한 7개 검사가 모두 일치했다. 모든 결과는 20건·`has_more: true`였다.

배포 후 tracemalloc 포함 warm 전체 열매는 1,184.4~1,199.1ms·Python peak 약 16.9MB, 까마귀과는 153.3~153.4ms였다. 별도 메모리 계측 없는 독립 검증에서 전체 427.4ms·까마귀과 57.6ms도 관측됐으나 다른 읽기 작업이 진행된 참고값으로, 계측 전후 속도 개선 주장에 사용하지 않는다.

공개 HTTP에서는 아래 세 실제 질문의 20종 모두 독립 계산한 점수가 내림차순임을 확인했다.

| 실제 질문 | 이전 HTTP | 배포 후 HTTP | 결과 |

| 까마귀과 중 열매를 먹는 새는? | 0.970초 | 1.028초 | 100·100·70·60·50×13·40×3 순 |

각 질문은 전후 한 번씩이고 HTTP에는 질의 분류가 포함된다. 이 수치만으로 성능 개선·회귀를 판정하지 않는다.

## 6. 한계 및 후속 과제

- 기존 근거 검증·JSON 파서를 재사용하고 서로 충돌하는 구성은 오류로 거절한다. 자료 없는 값을 새 사실로 생성하지 않는다.

- 기존 RG-203·RG-210 후속으로 기록했던 내용 중 정렬은 사용자 요청으로 RG-214에 신규 등록했다. 표시명 변경은 RG-407과 연결하며 기존 항목의 상태와 과거 기록은 보존한다.
