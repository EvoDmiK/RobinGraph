## 2. 해결 방안 및 안전 경계

- 영어 범주값은 typed condition이 실제로 주장한 정확한 값 구간에 한해 학명 후보에서 제외했다. 실제 분류명이나 다른 위치의 같은 문자열까지 지우지 않는다.
- 담화와 명시적 “제한 없음”을 질문 범위 metadata로 처리했다. 실제 제외·생물학적 부정·추가 조건을 삭제하는 방식으로 확장하지 않는다.
- 수치 보정은 유일한 정확한 원문 수치의 canonical 값과 raw threshold가 일치할 때 단위 label만 다룬다. 잘못된 수치 자체를 정답으로 교체하지 않는다.
- 자체 제외는 기존 검증이 증명한 경우에만 미해결 목록에서 정리했다. 다른 대상 제외나 추가 조건을 임의 제거하지 않는다.
- 조건·비교의 기능 어미는 원문의 수치·연산·내용을 유지하는 제한된 구간만 복구했다. 임의 의역을 허용하지 않는다.
- 관계 근거에 한 개의 literal 생략 placeholder가 들어간 경우 현재 기준 종과 원문 prefix·suffix가 유일하게 일치할 때만 복구했다. 기존 실행 계약·실제 감사는 유지한다.
- 특정 식물 먹이 공유는 명시적인 자료 부족 응답으로 처리했다. 자료 없는 관계를 생성하거나 일반 열매 조건으로 바꾸지 않는다.

```text
현재 원문·typed 조건 → 범주/이름·metadata·수치·관계 근거 확인
→ 증명된 구간만 보정 → 기존 계획 검증·감사 → 고정 그래프 조회 또는 자료 한계/보류
```

### 보완 과정에서 확인한 회귀

국명은 근거 있는 이름, 학명은 엄격한 2·3단어 원문 전체 이름을 기준으로 했다. `_LATIN`의 선택적 세 번째 단어로 아종명을 부모 종명으로 자르지 않도록 하고 API의 active identity 검사는 유지했다.

숫자 비교의 “무겁다/무겁다는”, “이상인/이상이라는” 차이를 보완하는 과정에서 기존 “짧은지” 요청의 8 subtest 회귀를 발견했다. 단일 토큰 기능 어미는 제한적으로 허용하고 “짧은지렁이/무겁다람쥐”는 계속 차단했다. 이후 실제 회귀에서 “초과라는/이하로/이상으로”가 차단돼 공유 `_PREDICATE_TAIL`의 조사·명사화·인용 어미를 보완했다.

독립 로컬 검사에서는 “아니라는” 부정을 긍정 조건으로 실행하는 safety failure 1건도 발견했다. 이를 실제 API 오실행으로 단정하지 않으며 `predicate-denial-safety-finding.json`과 `unit-predicate-before-denial.log`에 보존했다. 공통 `_COPULAR_DENIAL`을 25개 활용형의 경계 제한 패턴으로 확장해 수정하고 독립 검사를 통과했다. 기존 감사 false를 무시하는 방식으로 통과시키지 않았다.
