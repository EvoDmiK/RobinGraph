# 꼬까울새 파비콘 추가 — 2026-10-09

## 요청 배경과 목표

사용자가 투명 배경의 둥근 꼬까울새 이미지(`~/Downloads/robingraph.png`, 1254×1254 RGBA)를 파비콘으로 추가해 달라고 요청했다.
저장소의 `docs/assets/robingraph-logo.png`는 글자와 가지가 들어간 전체 로고라 다른 그림이며 파비콘 원본으로 쓰지 않았다.
작업 시작 전에 이미지는 채팅에 붙여 넣은 상태라 디스크에 파일이 없어서, 사용자에게 저장 경로를 받았다.
완료 범위는 코드 변경과 TEST 배포·검증까지이며 PROD 배포는 하지 않았다(아래 참조).

## 확인한 사실

- 파비콘 설정이 전혀 없었다(`<link rel="icon">`·`/favicon.ico` 라우트 없음).
- `src/robingraph/api/app.py`는 `/static/`으로 `_REQUIRED_CHAT_ASSETS`(index.html, chat.js, styles.css)와 `birds.*`만 서빙하고
  각 응답을 정해진 파일 묶음 단위로 읽는다. 이미지(바이너리)를 서빙하는 경로가 없어 HTML 태그 추가만으로는 해결되지 않았다.
- 같은 파일 읽기 함수(`_read_chat_asset_bundle`)는 열린 파일 기술자에서 읽고 빈 파일·비정규 파일을 거부하므로 아이콘에도 재사용했다.
- `pyproject.toml`의 package-data는 `*.html/*.js/*.css`만 포함해 PNG·ICO가 wheel에 빠질 상태였다.
- 기존 프런트엔드 테스트가 `index.html`의 `<link>`가 `/static/styles.css` 하나뿐이라고 단정하고 있었다.

## 변경 전후 동작

- 변경 전: 브라우저 탭 아이콘 없음(기본 아이콘), `/favicon.ico`는 404.
- 변경 후: 탭과 북마크에 꼬까울새 아이콘, iOS 홈 화면 추가 시 크림색 배경의 아이콘이 쓰인다.

작은 크기에서도 보이도록 잘라냈으므로 원본 전체 캔버스와 비율이 다르다. 원본 그림 자체는 수정하지 않았다.

설계 결정: 아이콘은 **선택적 자산**이다. 파일이 없거나 비어 있으면 아이콘 요청만 404이고, 채팅 UI는 `503 unavailable`로 바뀌지 않는다
(필수 자산 묶음에 넣지 않음). 허용 목록 밖의 이름(`/static/favicon.png` 등)은 404다.

## 남은 한계와 후속

- 실제 브라우저 탭·북마크·iOS 홈 화면에서 아이콘이 어떻게 보이는지는 직접 열어 확인하지 못했다(HTTP 응답과 이미지 크기·모양만 확인).
  브라우저가 파비콘을 오래 캐시하므로 확인할 때 강력 새로고침이 필요할 수 있다.
- 16px에서의 가독성은 눈으로 평가하지 않았다. ICO에 16px이 포함돼 있다.
- Android Chrome용 `manifest.webmanifest`와 512px 아이콘은 만들지 않았다(요청 범위 밖). 필요하면 `favicon-512.png` 생성 스크립트로 같은 방식으로 추가할 수 있다.
- 원본 PNG(1.3MB)는 저장소에 넣지 않았다. 더 큰 크기가 필요하면 `~/Downloads/robingraph.png`에서 다시 생성해야 한다.
- 백로그에는 이 작업을 등록하지 않았다.
