# 답변 오른쪽 위 사진 미리보기와 도감 카드 진입

> 후속 배포: 2026-10-10 사용자 요청으로 TEST·Production 배포를 완료했다. 실제 검증·이미지·배포 정보는 [배포 기록](2026-10-10-answer-preview-nas-production-deploy.md)을 따른다. 아래 미배포 설명은 최초 구현 완료 시점의 기록이다.

## 요청 배경과 목표

사용자가 국명 옆 영문명 병기에 이어, 답변의 오른쪽 위 빈 공간에 작은 새 사진과 도감 카드 진입을 묶자는 제안을 승인했다. 일반 종 소개 화면에서 해당 영역을 구현한다.

## 기존 구조와 변경 전후

종 소개는 기본 정보 뒤에 별도의 도감 카드 버튼을 배치했다. `buildSpeciesPopup`이 카드·대화상자·키보드·포커스·배율을 관리하므로 새 대화상자를 중복 생성하지 않고 기존 버튼을 사진 미리보기 형태로 사용한다. 일반 소개의 popup 요소를 설명 앞에 넣고 오른쪽으로 배치했다. 질문 주제별 답변·비교 결과의 기존 카드 진입은 유지한다.

PC 사진 영역은 148px, 모바일은 104px를 기준으로 컨테이너 폭의 38%를 넘지 않게 제한한다. 사진은 4:3으로 자르고 기본 정보 옆에 배치한다. 서식·보전 등급·먹이 요약은 사진 아래로 내려 겹침을 방지한다. 버튼 안에 `도감 카드 보기 ↗`를 표시하며 이미지 자체는 중복 읽기를 피하도록 빈 alt, 버튼에는 종 이름을 포함한 접근성 이름과 dialog 속성을 제공한다. 누르거나 키보드 Enter로 열면 기존 카드가 표시되며 닫으면 같은 버튼으로 포커스가 돌아온다.

## 사진·출처·후속 조회

프로필에 이미 전달된 사진 중 기존 이미지 URL 검증을 통과하는 첫 번째 사진을 사용한다. 기존 카드와 동일한 최대 6개 후보 범위다. 텍스트를 HTML로 해석하지 않고 Wikimedia 허용 URL 정책을 유지한다. 사진 출처와 라이선스는 카드의 출처 자료를 통해 기존 `답변 출처 보기`에 합쳐지며 새 중복 출처 목록을 만들지 않는다.

미리보기에는 로딩 상태, 대표 사진 없음, 이미지 요청 실패를 각각 표시한다. 작은 영역은 사진이 없어도 카드 버튼으로 동작한다. 기존 `더 알아보기`를 누른 뒤 사진·설명을 받는 정책을 유지하며 미리보기 때문에 추가 API/모델 호출을 자동 시작하지 않는다. 초기 응답이 사진 준비 전이면 자리표시자를 보이고, 기존 카드의 `updateEnrichment`가 사진을 받아오면 미리보기도 같은 자료로 갱신한다. 나중에 사진이 없는 결과가 들어오면 이전 사진을 제거한다.

## 변경 파일과 구현

- `src/robingraph/api/static/chat.js`: popup의 선택적 preview 구성, 로딩/오류/자료 없음 처리, 카드 사진 갱신 callback, 일반 답변에서 popup 위치 변경.
- `src/robingraph/api/static/styles.css`: 작은 미리보기, 사진 비율·자르기, PC/모바일 크기와 요약 영역 clear 배치.
- `tests/frontend/chat_ui.test.js`: 모의 DOM의 표준 insertBefore 지원, 기존 레이아웃의 새 popup 순서 반영, 지연 갱신·위험 URL 배제·실패·사진 제거·버튼 유지 회귀 검사.
- `docs/verification/assets/2026-10-10-answer-photo-preview.json`: 실제 Chrome 배치·상호작용 결과.

## 실제 검증 결과와 실패 이력

최종 `node --test tests/frontend/*.test.js`: 299개 통과, 실패 0, 건너뜀 0. 최초 실행은 popup 안에서 카드 내부 전용 clearNode 함수를 호출한 범위 오류로 30개 검사에 영향을 주었다. popup에서 자체 노드 제거를 수행하도록 수정하고, 모의 DOM의 insertBefore 및 새 배치 기대값을 반영한 뒤 전체 통과했다. 최종 검사는 로딩 상태·이미지 eager 로딩·고정 비율 CSS 보완 이후 다시 실행했다.

실제 TEST API에서 청둥오리 프로필을 읽고 공개 TEST 페이지의 JS/CSS만 로컬 수정본으로 가로챘다. 채팅 POST 응답은 해당 프로필을 재생한 것이므로 새 Jev 라우팅·모델 답변 검증은 아니다. 320·390·768·1280px에서 실제 프로필, 사진 없음, 위험 URL, 네트워크 이미지 실패, 추가 자료 대기 상태의 5사례씩 총 20개 통과했다. 실제 프로필 4설정에서는 미리보기 이미지가 complete이며 naturalWidth가 0보다 큰 것을 기다려 실제 로드를 확인했다. 나머지 16설정은 통제한 예외 자료다.

20설정 모두 가로 넘침 없음, 요약이 사진 아래로 배치됨, 주 미리보기 진입 1개, 키보드 Enter로 동일 종 카드 열림, 닫은 뒤 opener 포커스 복원, 페이지 오류 0을 확인했다. 최초 브라우저 검사에서 미리보기의 모든 img를 세어 숨겨진 카드 사진까지 포함한 오류는 버튼 내부로 범위를 좁혔다. 이미지 lazy 로딩 때문에 실패 상태를 기다리는 검사가 지연된 문제는 미리보기만 eager 로딩으로 바꾸고, 사진의 위치·비율과 로딩 표시를 보완하여 최종 재검증했다. PC와 모바일 스크린샷도 확인했다.

물리 모바일 기기·Safari, 전체 종 HTTP, 새 백엔드 또는 DB 검증은 수행하지 않았다. 사진의 object-fit:cover로 가장자리가 잘릴 수 있으며 큰 원본은 도감 카드에서 확인한다.

## Git·배포·남은 범위

`dev-codex`에 코드·테스트·검증 JSON·작업 기록을 함께 커밋하고 push한다. main/dev에는 병합하지 않으며 이번 요청에서 서버 배포는 수행하지 않는다. 아직 공개 TEST/Production 정적 자산에 반영된 것으로 안내하지 않는다. API·DB 자료는 변경하지 않아 DB 이관은 해당하지 않는다. graphify AST 갱신을 완료하며 SQL 추출 의존성 및 커뮤니티 이름 경고는 기존 도구 한계다. 이후 배포 시 공개 정적 자산과 실제 질문·지연 사진 갱신을 확인한다.
