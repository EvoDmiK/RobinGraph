# 세 에이전트 역할 정립과 지침 전파

## 요청 배경과 목표

사용자는 dev-codex 아래 두 Orca 워크트리의 에이전트가 보이는지 확인한 뒤, 프로젝트를 살펴 역할을 추론하여 AGENTS.md에 기록하고 두 에이전트에게 전파하도록 요청했다. 이번 결과물은 프로젝트에 근거한 담당 업무, 충돌 방지 규칙, 최초 점검 지시와 실제 전파다. 앱 기능 구현이나 새로운 배포를 요청한 작업은 아니다.

## 확인 근거와 판단

- README.md는 한국어 조류 질문, 근거와 자료 부족 표시, 국명 우선, 도감 카드, 종 관계 비교, Neo4j·PostgreSQL과 문헌 검색을 설명한다.
- pyproject.toml과 src/robingraph/api/app.py, retrieval/ 및 api/static/의 파일 구조를 확인했다. Python API·데이터 계층과 HTML·JS·CSS 화면 계층을 나누면 작업 충돌을 줄일 수 있다.
- 2026-10-14 전체 TEST 검증, 로컬 TEST 시작 수정, OrbStack 재시작 후 확인, 서비스 도메인 정리 기록을 읽었다. 과거 전체 검증 문서의 중계 의존성은 이후 직접 연결 복구·중계 제거 기록으로 해소됐으므로 현재 장애로 분류하지 않았다.
- 해당 기록에서 일회용 DB 전용 테스트, 실기기·브라우저 범위, 물리 재부팅 검증과 도메인 변경 후 테스트 재실행이 후속 확인으로 남아 있음을 확인했다. 이들은 기록상 한계이며 이번에 재현한 결함이 아니다.
- graphify query를 우선 시도했지만 현재 dev-codex에 graphify-out/graph.json이 없어 실패했다. wiki/index.md도 없었다. 새 그래프 생성 대신 원문 문서와 소스 구조를 직접 읽었다.
- Orca 조회에서 dev-claude는 Claude 터미널, 표시 이름 dev-agy는 실제 main 폴더의 Antigravity 터미널임을 확인했다. 두 작업 트리는 최초 확인 시 변경 사항이 없었고 기존 AGENTS.md 내용도 확인했다.

## 변경 전후와 구현 내용

기존 AGENTS.md에는 Graphify 사용, 상세 작업 문서, 운영 배포 승인 규칙이 있었으며 에이전트별 역할과 파일 소유 경계는 없었다. 기존 내용을 보존하고 「에이전트 역할과 협업 지침 (2026-10-15)」을 추가했다.

| 담당 | 범위 | 최초 지시 |
|---|---|---|
| Codex / dev-codex | 요구사항 분해, 공통 계약, 환경·배포 스크립트, 통합 검토와 TEST 검증 | 지침 동기화·전파 확인, 최신 기록 기준 후속 범위 정리 |
| Claude / dev-claude | 조류 데이터, 종 범위·국명·보전·형질 출처, 검색·라우팅·API | 코드·테스트를 읽어 위험과 검증 공백 최대 3개 보고 |
| Antigravity / dev-agy | 도감·채팅·비교 화면, PC·모바일 조작과 접근성 | 정적 자산·검증 자산을 읽어 위험과 검증 공백 최대 3개 보고 |

공통 API 변경 조율, 자기 워크트리에서만 수정, 공유 TEST 인덱스 보호, 증거 기반 결과 보고와 인증 정보 제외를 명시했다. 최초 지시는 읽기 중심 점검이며 앱 코드 수정·DB 쓰기·서비스 재시작·배포·commit/push/병합을 포함하지 않는다. 운영 배포의 별도 명시 승인 규칙을 유지했다. 이후 구현 범위는 사용자 요청과 점검 근거에 따라 정한다.

변경 파일은 dev-codex/AGENTS.md, dev-claude/AGENTS.md, main/AGENTS.md 및 본 문서다. 자식 파일은 기존 지침을 보존하면서 공통 역할 절을 추가했다. 부모·자식 사이의 Git 병합이나 자동 동기화에 의존하지 않고 파일별로 적용했다. 에이전트가 보고 파일을 작성할 경우 각자 별도의 날짜·역할 파일만 쓰도록 지정했다.

## 검증 방법과 실제 결과

- 세 파일의 추가 역할 절 문자열 동일성 검사: 통과. 파일별 기존 지침은 유지했다.
- 세 워크트리 git diff --check: 모두 통과. 역할 절 SHA-256 앞 16자도 세 파일 모두 bbe800383d58fdc4로 일치했다.
- Claude 터미널에 Orca terminal send로 지시: accepted=true, input_accepted 및 turn_started 확인. 이후 terminal read에서 AGENTS.md를 읽는 명령과 작업 진행 표시를 확인했다.
- Antigravity 터미널에 같은 범위의 역할별 지시: accepted=true, input_accepted 확인. provider=unsupported이므로 CLI의 turn_started 증명은 제공되지 않았다. terminal read에서 전체 지시가 제출된 기록과 처리 진행 표시를 확인했다. 중복 전송하지 않았다.
- 두 에이전트의 점검 보고 완료 여부는 이번 전파 성공과 별개다. 본 문서는 점검 결과 완료를 주장하지 않는다.
- 앱 단위·통합·브라우저 테스트: 실행하지 않았다. 문서 및 지침 전파만 변경했기 때문이다. fixture·mock·실제 DB/API 검증 모두 새로 실행하지 않았다. 이전 TEST 통과 기록을 이번 실행 결과로 합산하지 않는다.

## 배포·커밋·남은 한계와 후속 사항

Production 및 TEST 배포, 컨테이너 재시작, DB 변경, commit/push/병합은 수행하지 않았다. 지침과 본 문서는 미커밋이다. Obsidian 기록은 요청되지 않아 수행하지 않았다. 앱 코드 변경이 없어 Graphify AST 갱신은 수행하지 않았다. 현재 그래프 부재를 앱 실행 장애로 해석하지 않는다.

두 에이전트의 최초 점검 결과를 후속 작업 선택에 사용한다. 현재 역할은 파일 경계를 정한 것으로 모든 잠재 문제 수정의 포괄적 승인이 아니다. AGENTS.md를 읽고 따른다는 최종 자기 보고는 각 에이전트의 후속 응답에서 확인할 수 있으며, 전파 시점에는 터미널 제출·처리 상태까지 확인했다.
