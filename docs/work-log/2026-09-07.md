## 종료 상태와 다음 작업

- NAS workflow는 **inactive**다. Schedule Trigger는 `0 2 * * *`로 저장되어 있지만 workflow를 publish하기 전에는 자동 실행되지 않는다.
- community node 전환본을 Manual Trigger로 실행해 반환 count, cursor 갱신과 Discord 알림을 확인해야 한다.
- n8n Public API 스키마는 UI 전용 `concurrency` 필드를 받지 않는다. 운영 publish 전에 n8n UI에서 workflow concurrency를 1로 확인해야 한다.
- 현재는 page hash와 source URI를 보존하며 원본 response body 자체를 영속 파일로 보관하지 않는다. 원본 장기 보존이 필요하면 NAS 전용 volume과 파일 노드를 추가한다.
- GBIF taxon key는 승인된 AviList crosswalk가 없으므로 `ExternalTaxonConcept`로 저장한다. canonical `Taxon` 연결은 별도 승인 데이터가 준비된 뒤 수행한다.
- occurrence 일반명은 언어 정보가 없으면 `vernacular_name_raw`로만 보존한다. 한국어 표준명은 NIBR 출처와 이용조건을 확정한 뒤 별도 `VernacularName(language='ko')`으로 추가한다.
- 운영 활성화 뒤에는 첫 자동 실행의 GBIF 기간, 적재량, quarantine 비율과 Discord 알림을 확인한다.

상세 운영 절차는 [n8n 실행 런북](../n8n/README.md), 후보 비교와 최종 계약은 [n8n 최종 설계](../n8n/final-operational-ingest.md)에 있다.

전환본은 NAS workflow `Mw9tbGM9vyzu6X1F`에 백업 후 반영했다(15개 노드, inactive). 전체 테스트는 115개 중 94개 통과, opt-in Neo4j 테스트 21개 skip, 실패 0이었다. Code 노드와 Cypher expression의 JavaScript 구문 검사도 통과했다. 전환 후 실제 적재 실행은 아직 수행하지 않았다.

## 임베딩·검색과 테스트 UI 확인

현재 n8n workflow는 GBIF 수집과 그래프 적재까지만 담당하며 임베딩이나 검색은 실행하지 않는다. 저장소의 하이브리드 검색은 fixture 문서 청크를 대상으로 다음 별도 CLI 경로에 구현돼 있다.

- `index-neo4j-fixture --embeddings`: 문서 청크를 `retrieval.passage`로 임베딩하고 Neo4j vector index에 저장
- `search-neo4j --hybrid`: 질문을 `retrieval.query`로 임베딩하고 full-text/vector 결과를 결합

후속 구현에서 FastAPI에 `POST /v1/search`를 추가했다. Swagger에서 `fulltext`와
`hybrid` 모드를 선택하고 결과 점수·채널·출처·경고를 확인할 수 있다. Jina의
일시적 요청 실패는 전문 검색으로 폴백하며, 검색 backend 설정/연결 실패는 503을
반환한다. GBIF `BirdTaxon`·`Observation`은 아직 검색용 문서 청크나 vector
index에 포함되지 않는다.

## NAS 서비스 배포 준비

기존 Django 컨테이너와 분리된 `robingraph-api` 이미지를 만들 수 있도록 `Dockerfile`, `compose.nas.yml`, `.env.nas.example`, `.dockerignore`와 NAS 배포 런북을 추가했다. API는 호스트 포트를 점유하지 않고 `robingraph-edge` 외부 Docker 네트워크에서 NPM과 통신한다. NPM의 `aviary.dove-nest.com`은 `http://robingraph-api:8000`으로 전달하도록 정의했다.

컨테이너는 비루트 사용자, read-only root filesystem, `/tmp` tmpfs, capability 제거, `no-new-privileges`, healthcheck, 자동 재시작과 로그 rotation을 사용한다. 첫 배포는 현재 동작이 확인된 `serve-fixture`이며, `.env.nas`의 실행 모드와 Neo4j 자격 증명을 설정하면 `serve-neo4j`로 전환할 수 있다. 현재 실제 GBIF 그래프 검색은 API에 연결되지 않았다는 제한도 런북에 명시했다.
