# RG-003 — 자연어 질문으로 그래프 정보 조회

RG-003의 요청은 탐색 버튼만 추가하는 것이 아니라 **질문에 맞는 그래프 자료를 바로 조회해 답변하는 것**이다. 앞선 생태 탐색 버튼 작업의 범위를 잘못 좁혔던 해석을 정정하고, 기존 자료·관계 조회를 채팅 질문에 연결한다.

## 질문과 응답

| 질문 예 | 직접 제공하는 내용 |
|---|---|
| 왜가리는 무엇을 먹고 사니? / 왜가리의 먹이는 뭐야? | 출처가 있는 먹이 구성비 또는 먹이 범주 |
| 청둥오리와 비슷한 종은 어떤게 있니? | 같은 속·과의 후보 이름·분류 관계·출처 |
| 청둥오리와 같은 속의 새는? | 같은 속 후보만 |
| 왜가리와 먹이가 비슷한 새는? | 같은 자료의 먹이 생태 범주 후보 |
| 왜가리와 서식 환경이 비슷한 새는? | 같은 자료의 서식 환경 범주 후보 |
| 왜가리는 어디 살아? | 확인된 서식 환경, 상세 지역을 추측하지 않음 |
| 해오라기는 밤에 활동해? | 출처가 있는 검토 활동 시간 설명 |
| 청둥오리 생김새 알려줘 | 출처가 있는 외관 설명 또는 자료 미확인 안내 |

이 표현과 지원하는 변형을 인식한다. 모든 자유로운 한국어 질문이나 대명사·이전 대화를 활용한 생략 질문을 해결한 범위는 아니다. 의도·종을 인식하지 못한 질문은 기존 분류 경로를 따르며 임의 Cypher를 생성하지 않는다.

## 처리 흐름

`POST /v1/chat`에서 종 이름과 주제(먹이·서식 환경·활동 시간·외관·관련 종·생태 관련 종)를 먼저 추출한다. 명시적 문헌·관찰 질문은 기존 경로를 유지한다.

1. 검토 이름 관계가 있으면 먼저 확인한다. 여러 후보와 가축형은 임의로 야생 종을 선택하지 않는다.
2. 고유 통칭은 연결된 종의 프로필을 조회하고 이름 관계와 프로필의 taxon ID·개념집합·분류판이 일치하는지 확인한다.
3. 정확한 대상 프로필의 직접 형질·설명만 사용한다. 아종의 부모 종 참고 형질을 답변으로 대입하지 않는다.
4. 관련 종 질문은 기존 분류 관계 또는 명시한 생태 관계 조회를 실행한다. 결과와 프로필의 ID·분류판도 대조한다.
5. 질문에 해당하는 정보와 출처를 답변 첫 부분에 표시한다. 후보 목록도 바로 펼쳐 제공하며 추가 조회 버튼을 누를 필요가 없다.
6. 후보 비교는 새 말풍선에서 두 종의 자료·카드를 제공한다. 카드 열기와 기존 탐색 버튼도 유지한다.

자동·종 정보 모드에서 질문의 종과 명시한 필터의 종이 다르면 확인 질문을 반환한다. 다른 종의 자료를 질문의 답처럼 표시하지 않는다.

## 근거와 데이터 해석

- 먹이 구성비는 같은 자료의 양의 유한한 값만 사용한다. 지역·계절·개체의 고정 식단으로 단정하지 않는다.
- 구성비가 없으면 출처가 있는 먹이 유형·생태 범주를 표시한다. 수생동물 포식이라는 범주만으로 물고기나 특정 먹이종을 추측하지 않는다.
- 먹이·활동 시간 등 질문에 맞는 자료가 없으면 그 정보를 제공하지 못했다고 답한다. 일반 소개를 질문의 답처럼 대신하지 않는다.
- 같은 속·과는 분류상 관계다. 외형 유사도 또는 계통상 가장 가까운 순위라고 주장하지 않는다.
- 생태 관계는 같은 자료·릴리스·원문 분류값을 비교한다. 대상과 각 후보의 증거를 분리해 표시한다.
- 관련 종 목록은 한국어 이름을 우선하고 없으면 허용된 영어 이름을 사용한다. 양쪽이 없으면 학명이다. 범주별 최대 12개와 추가 결과 안내를 유지한다.
- 야행성 원자료 0은 활동 부재로 단정하지 않는다. 해오라기 검토 설명은 고정 분류판·정확한 대상에만 적용한다.

## 응답 계약과 구현 위치

기존 `result.kind=profile`과 `result.profile`을 유지하며 선택 필드 `result.question_answer`를 추가한다. 이 객체에는 `topic`, `title`, `text`, 출처가 있는 `items`, 직접 조회한 `relations`가 들어간다. 질문에 답할 근거가 없으면 `disposition=abstain`이다.

질문 추출·근거별 응답은 `retrieval/species_questions.py`, 채팅 연결은 `api/app.py`, 직접 답변·후보 목록은 `api/static/chat.js`에서 처리한다. 임베딩이나 모델 호출이 질문 인식의 필수 조건은 아니다. 프로필 설명·사진 조회 등 기존 서비스 호출은 별도로 유지한다.

구체적인 배포·테스트 결과는 해당 검증 기록을 따른다. 생태 조회의 근거 정책은 [생태 관계](ecological-relations.md), 이름 관계는 [통칭·가축형](name-relations.md), 아종 정책은 [아종 카드](subspecies-cards.md)에 있다.
