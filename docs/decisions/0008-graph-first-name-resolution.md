# ADR-0008: 그래프 우선 이름 해소와 벡터 후보 확인

- 상태: 사용자 요청에 따른 구현 방향 확정, 검증 결과는 작업기록 참조
- 날짜: 2026-10-15
- 관련: RG-202 요청 범위 정정, ADR-0002·0005

## 배경

사용자가 원하는 것은 문헌에서 개체·사실을 추출하는 HippoRAG가 아니라, 질문 속 이름을 기존 조류 노드에 연결하는 흐름이다. `흰뺨 검둥 오리에 대해 알고 싶어`를 이름 표현과 질문 의도로 나누고, 그래프에서 못 찾을 때 이름 벡터로 후보를 찾는다. 앞선 문헌 감사와 MRR 수정 결과는 보존하되 다문헌 50문항 확보를 이 이름 해소 기능의 선행 조건으로 삼지 않는다.

## 결정

1. 원문 질문, 이름 표현, 질문 의도, 정규 조류 식별자를 구분한다. 조류 노드는 기존 활성 분류판의 ID를 사용한다.
2. 기존 국명·학명·영어 이름·검토 이름 관계를 우선 조회한다. NFC·공백 정규화 후에도 활성 그래프가 동일한 노드를 반환해야 자동 연결한다.
3. 그래프에서 이름이 없을 때만 이름 표현을 embed_query하고 검토된 이름 검색 텍스트의 embed_documents 벡터와 코사인으로 비교한다. 문헌 청크 벡터를 조류 이름 벡터로 대신 쓰지 않는다.
4. 초기 후보 범위는 검토 국명과 활성 그래프의 식별자·학명·영어 이름·출처 정책이 일치하는 종이다. 초기 v2025b의 850개 국명에서 시작했으며, 2026-10-19 검토 국외 6종의 영어 이름·학명 텍스트를 포함한 855종으로 확장했다. 최대 1,000개로 제한한다. 전체 11,131종·모든 아종의 유사 이름 검색 지원으로 표현하지 않는다.
5. 벡터는 최대 3개 후보를 제시하며 자동으로 같은 종이라고 확정하지 않는다. 각 후보의 학명을 그래프에서 다시 해소하여 ID·종 rank·분류판을 확인한다. 사용자가 선택하면 해당 학명을 포함한 질문을 다시 보내 기존 그래프 경로로 재검사한다.
6. 후보 선택 시 원래 먹이·서식 등 질문 주제를 유지한다. 처음 질문과 후보 확인 대화를 보존한다. 점수는 순위 신호이며 확률·정답 신뢰도로 화면에 표시하지 않는다.
7. 이름 후보가 없거나 모델·프로필·그래프·활성 문맥이 유효하지 않으면 답변을 보류한다. 원문 질문 전체를 이름으로 임베딩하지 않는다. 명시적 관찰·문헌 경로와 질문/필터 불일치 방지는 유지한다.

## 저장·출처·운영 경계

이름 표현과 노드 연결은 ChatResponse.entity_resolution의 요청별 정보로 반환한다. 기존 대화·추적 체계가 이 정보를 보관할 수 있지만 새 Query/Alias 노드나 영구 별칭을 만들지 않는다. 질문 표현을 자동으로 국명 자료에 추가하지 않는다. 그래프에서 확인한 ID·concept_set_id·taxonomy_release를 프로필 결과와 다시 비교한다.

초기 구현은 Jina 이름 벡터를 프로세스 메모리에 캐시했지만, 사용자 후속 요청에 따라 Neo4j 영구 저장과 벡터 인덱스 조회로 이전한다. `TaxonNameVectorEntry`가 이름·taxon ID·학명·텍스트 해시·임베딩 프로필·분류 문맥을 보관하고 기존 조류 노드에 `NAME_VECTOR_OF`로 연결한다. 활성 자료에만 `TaxonNameVector` 라벨과 `name_vector`를 두며, 별도 `robingraphTaxonNameVector` 인덱스에서 검색한다. 활성 catalog 지문이 현재 검토 이름 목록·모델·차원·정규화·분류판과 일치해야 한다. 기존 문헌 인덱스와 조류 원자료는 변경하지 않는다.

채팅 경로는 질문 이름의 `embed_query`와 읽기 전용 인덱스 조회만 수행하며, 이름 목록의 `embed_documents`·schema 생성·DB 쓰기·메모리 벡터 대조를 하지 않는다. 이름 색인은 TEST 환경의 `scripts/index_taxon_name_vectors.py`에서 별도로 실행한다. 기본 dry-run은 읽기와 준비 수량 확인만 하며 `--apply`가 있어야 누락/변경 이름을 임베딩하고 원자적으로 활성 catalog를 교체한다. 같은 자료의 재실행은 저장된 벡터를 재사용한다. 모델/차원/문맥/텍스트 변경이나 이름 삭제를 검사하고 호환되지 않는 기존 인덱스를 자동 삭제·교체하지 않는다.

Neo4j5.26의 cosine 인덱스 점수는 0~1 범위이므로 저장소 어댑터가 `2*score-1`로 기존 raw cosine 기준에 맞춘다. 이 규약은 [Neo4j 공식 문서](https://neo4j.com/docs/cypher-manual/5/indexes/semantic-indexes/vector-indexes/)와 실제 별도5.26.30 DB에서 직교 벡터 점수0.5·어댑터 반환0.0으로 확인했다. 기존 후보 기준과 사용자 확인 정책은 유지한다. 인덱스는 근사 이웃 검색이므로 메모리 전수 비교와 모든 입력의 순위가 같다고 보장하지 않는다.

실측 조정에 사용한 일부 오타의 정답 후보 점수는 약 0.29~0.35, 비교한 비조류 단어는 최대 약 0.20이었다. 후보 하한 0.25는 작은 조정 사례를 바탕으로 한 제시 기준일 뿐 넓은 정확도 보장이나 자동 해소 기준이 아니다. 초기 메모리 방식의 첫 구축은 약28~29초였다. Neo4j 이전 후에는 앱 재시작 때 목록을 다시 임베딩하지 않지만, 질문 이름의 Jina 호출과 DB 조회 지연은 남는다. 측정 결과는 별도 작업 기록에서 범위와 함께 관리한다.

### 후속 보완: 천둥오리의 후보 누락

실제 NAS에서 `천둥오리`의 청둥오리 cosine은 0.2138(2위)로 일반 하한에 미달했다. 전역 하한은 유지한다. 벡터 상위 10개에 일반 하한을 넘는 후보가 하나도 없을 때만 cosine 0.20 이상이면서 한국어 이름의 자모 한 글자만 치환된 후보를 허용한다. 공백을 제외한 이름이 최소 4음절·동일 음절 길이이고, NFD 분해 길이도 같으며 정확히 자모 하나만 달라야 한다. 이 보완은 한글 오타 전반의 편집 거리 검색이나 자동 정정이 아니다. 후보는 동일하게 그래프 ID·분류판으로 재검증하고 사용자 확인을 거친다. method=vector와 score는 실제 벡터 계산 결과를 유지하며 별칭은 저장하지 않는다.

공백이 섞인 오타도 같은 결과가 되도록 한국어 이름 내부 공백을 제거한 표현으로 벡터 질의를 한다. 원문 mention과 질문은 보존한다. 낮은 점수·철자가 먼 입력·짧은 입력은 이 보완으로 통과시키지 않는다. 이름 벡터 또는 그래프가 불능일 때 철자만으로 후보를 만들지 않는다. 상세 재현·회귀·배포 결과는 후속 작업 기록을 따른다.

## 완료 확인

띄어쓰기 질문의 그래프 직접 연결, 오타의 벡터 후보·확인 후 그래프 조회, 주제 보존, 동점·없는 이름·모델 장애·오래된 분류판·잘못된 벡터에서의 보류를 확인한다. 단위·가짜 벡터 검증과 실제 TEST DB/Jina/API·브라우저 검증을 구별한다. Production 배포는 사용자 별도 승인 전 수행하지 않는다.


## 2026-10-19 후속: 검토 국외 6종의 이름 검색

기존 검토 국명 후보는 유지한다. RG-406의 pinned KR 분포 자료에서 outside로 검토된 6종만
활성 AviList 종 ID·학명·허용 영어 원자료 이름에 대조해 영어 이름+학명을 이름 벡터 텍스트에 포함한다.
한국어 이름이 이미 검증된 Kea는 한국어 텍스트도 함께 유지한다. 새 국명·별칭·분포 판정은 만들지 않는다.
850→855는 새로 추가한 5종과 기존 Kea 1종 텍스트 보완의 결과다. 기존 849개 벡터는 재임베딩하지 않는다.
카탈로그의 역사적 ID reviewed-korean-taxon-names는 기존 인덱스 호환을 위해 유지한다.

일반 cosine 하한과 기존 한국어 자모 보완은 유지한다. 일반/한국어 보완 후보가 없을 때만,
검토 국외 집합의 영어 원자료 이름·학명과 Latin 입력이 한 글자 삽입/삭제/치환 또는 인접 전치인 경우를
확인 후보로 제시한다. 입력은 최소 4글자, 원자료 이름은 최소 3글자이며 Latin 알파벳·공백·하이픈으로 제한한다.
종을 활성 그래프에서 다시 검증해야 하고, 임베딩/벡터 저장소가 실패하면 철자만으로 후보를 만들지 않는다.
이 분기의 점수 하한은 일반 검색과 구별하며 실제 cosine 점수 자체는 낮아도 그대로 표시한다.
이는 이름 확인을 위한 순위 신호이며 신뢰도·자동 식별 확률이 아니다.

국외 범위에서 이 확인을 수행한다. 전체 범위도 일반 후보가 없을 때 같은 검토 집합을 추가 확인하되
같은 질의 벡터를 재사용해 두 번째 embed_query 요청을 만들지 않는다. 전체는 기존 한국어 우선 표시,
국외는 검증 영어 이름 우선을 유지한다. 다른 범위의 후보를 섞거나 점수를 인위적으로 올리지 않는다.

현재 고정 6종·정해진 오타 사례의 검증이며 모든 영어 오타/전체 11,131종으로 일반화하지 않는다.
실제 결과와 배포·미검증 범위는 [후속 작업 기록](../work-log/2026-10-19-rg406-outside-name-search.md)을 따른다.
