# ADR-0001: MVP 기본 데이터베이스

- 상태: Proposed
- 작성일: 2026-09-03
- 결정 대상: RobinGraph 로컬 MVP

## 맥락

MVP는 분류 관계, 관찰 기록, 장소, 서식지, 미디어, 문헌 근거를 연결해서 탐색해야 한다. 자연어 문헌 검색도 필요하므로 그래프 탐색, 전문 검색, 벡터 검색을 함께 제공해야 한다. 개발자는 1명이며 로컬 실행과 낮은 운영 복잡도가 우선이다.

## 결정

Neo4j Community Edition 한 인스턴스를 도메인 그래프와 문헌 Chunk 벡터 인덱스의 기본 저장소로 사용한다. 전문 검색도 같은 인스턴스에서 처리하고, 검색 결과 결합은 애플리케이션 계층에서 수행한다.

이 결정은 MVP에만 적용한다. 관찰 기록과 문헌 청크의 규모 및 실제 성능을 측정한 후 유지 여부를 다시 판단한다.

## 이유

- Cypher와 속성 그래프가 분류·서식지·지역의 다단계 관계를 직접 표현한다.
- 전문·벡터 인덱스를 같은 저장소에서 사용해 두 데이터베이스 간 동기화를 피할 수 있다.
- Python 공식 드라이버와 로컬 시각화 도구가 있어 1인 개발의 디버깅 비용이 낮다.
- 질문 계획을 허용된 Cypher 템플릿으로 제한하기 쉽다.

## 검토한 대안

### PostgreSQL + Apache AGE + pgvector

관계형 데이터, 공간 확장, 그래프, 벡터를 한 시스템에서 다룰 수 있고 라이선스가 허용적이다. 대규모 관찰 팩트와 PostGIS가 핵심이 되면 유력하다. MVP에서는 AGE 버전 호환성과 SQL 안의 Cypher 호출 방식이 개발 부담을 늘린다고 판단했다.

### Neo4j + Qdrant

벡터와 하이브리드 검색 기능은 강하지만 ID·삭제·재색인과 백업을 두 시스템에서 맞춰야 한다. 문헌 청크가 수백만 건이 되거나 Neo4j vector 검색이 평가 목표를 충족하지 못할 때 검증한다.

## 결과와 제약

- 단일 인스턴스 장애와 오프라인 백업 시간을 허용한다.
- Neo4j Community의 배포·라이선스 조건을 제품 배포 전에 다시 검토한다.
- 관찰 100만 건 또는 청크 100만 건에 도달하기 전에 부하 평가를 수행한다.
- 모든 저장소 접근은 repository 인터페이스 뒤에 둬 전환 비용을 제한한다.
- 임베딩 모델별로 별도 인덱스와 버전을 유지한다.

## 재검토 조건

- 10만 관찰·1만 청크 기준 LLM 제외 검색 p95가 반복해서 2초를 넘는다.
- 관찰 기반 공간 집계가 핵심 사용 사례가 된다.
- 단일 서버 중단을 허용할 수 없는 공개 서비스가 된다.
- Gold evidence Recall@10이 목표인 90%에 미달하고 원인이 vector 인덱스로 확인된다.

## 확정 전에 필요한 확인

- 목표 배포가 Neo4j Community 라이선스 조건에 맞는지
- 개발 장비의 메모리와 디스크
- 첫 데이터 스냅샷의 실제 관찰·청크 수
- 민감 좌표를 Neo4j에 원본으로 저장할지 별도 보호 저장소에 둘지
