# RG-409 앞면 오디오·뒷면 출처 분리 — 독립 검토

2026-11-02. dev-claude AGENTS 확인 후 API·출처 계약을 읽기 전용으로 검토했다. 앱 코드·DB·Git·배포는 변경하지 않았다.

## API·자료 판단

- API 변경 불필요. 기존 `recordings[]`의 `id`, `scientific_name`, `audio_url`, `title`, `creator`, `source_url`, `license_name`, `license_url` 및 선택 필드 `recording_type`, `recorded_at`, `location`을 그대로 양면에 나눠 표시하면 된다. `recording_availability`와 기본 도감 즉시 조회도 그대로 유지한다.
- 앞면은 네이티브 오디오와 같은 카드의 뒷면 귀속 정보로 가는 명확한 버튼/연결을 둔다. 뒷면에서 각 녹음별 제목·원저자·원문 URL·라이선스명/URL·기존 날짜/지역/소리 유형을 보존한다. 녹음이 여러 개면 앞면 플레이어와 뒷면 항목이 같은 `id`/제목으로 구분되어야 한다.
- CC BY 4.0 §3(a)(2)는 맥락에 맞는 합리적인 표시와 귀속 정보 리소스 링크를 허용한다. CC BY-SA 3.0 §4(c)는 저자·제목·지정 URI 등을 매체에 맞는 합리적인 방식으로 표시하도록 한다. 따라서 바로 옆의 클릭 가능한 “출처·라이선스: 뒷면 보기”와 같은 카드의 실제 귀속 정보 연결은 이 요구를 유지할 수 있는 UI 구성이다. 단순히 “뒷면”이라는 글자만 두고 찾기 어렵게 숨기는 방식은 승인 판단에 포함하지 않는다. 이는 원본 라이선스 조항에 근거한 구현 검토이며 모든 상황의 법적 적합성을 확정하는 판단은 아니다.
- 기존 CC BY-SA 녹음은 이번 위치 변경으로 새로 수집·편집·임베딩하는 것이 아니다. 기존 소스별 허용 정책과 파일별 license guard를 그대로 보존한다. Proposed 상태의 ADR-0003을 이번 레이아웃 요청의 새 승인 차단으로 해석하지 않았다.

## UI 결과 검토 시 확인할 사항

1. 앞면 재생 중 뒷면 이동·팝업 닫기·다른 종 재생·카드 제거·화면 정리에서 재생이 멈추는가. 기존 코드는 오디오가 뒷면에 있어 `showFace(!showBack)` 때만 정지하므로 위치 이동 시 방향 또는 공통 정지 동작을 함께 맞춰야 한다.
2. native `controls` / `preload=none` / 이름을 포함한 `aria-label` / autoplay 없음 / 오디오 URL allowlist를 보존하는가. 오디오의 키보드·포인터 조작이 카드 뒤집기나 드래그를 유발하지 않아야 한다.
3. 출처 버튼이 키보드로 작동하고 해당 뒷면을 열며, 숨겨진 면의 inert/aria-hidden 처리와 초점이 정합적인가. 같은 카드 인스턴스에서 여러 녹음을 구별할 수 있어야 한다.
4. 사진만 갱신하는 enrichment에서는 녹음/메타데이터가 유지되고, 명시적 recordings=[]에서는 양면 목록과 기존 플레이어가 함께 정리되는가. 자료 없음·조회 실패·pending 문구를 혼동하지 않아야 한다.

## UI 완료본 독립 검토 결과

`/tmp/robingraph-audio-front-20261102/ui.patch`의 JS·CSS·회귀 테스트 diff를 확인했다. **수정 요청 없이 승인**한다.

- API/Python/DB 변경이 없고, 기존 녹음 배열의 필수·선택 메타데이터를 지우거나 재해석하지 않는다. 뒷면은 기존 제목·저작자·원문·라이선스·소리 유형·녹음일·지역 렌더링을 유지한다.
- 플레이어 DOM 한 개를 앞면 사진 바로 아래로 옮긴다. 기존 `controls`, `preload=none`, 오디오 URL 검증과 제목을 포함한 접근 가능한 이름을 유지하며 autoplay를 추가하지 않는다.
- `출처: 뒷면`은 실제 button이고 녹음 제목을 포함한 aria-label 및 카드 인스턴스별 고유 aria-controls를 가진다. click은 진행 중 flip을 정리하고 뒷면 표시→출처 details 열기→summary 초점 순서로 이동한다. 기존 inert/aria-hidden 갱신은 showFace에서 보존한다.
- 재생면이 앞면으로 바뀐 것에 맞춰 `showFace(showBack)` 때 정지하도록 변경했다. 다른 종 재생·팝업 닫기·카드 정리·DOM 제거의 기존 정지 훅은 유지한다. 뒷면의 메타데이터 details를 접는 것만으로 앞면 플레이어를 정지시키던 연결은 제거했으며, 위치 분리에 맞는 변경이다.
- 사진만 갱신하면 기존 녹음을 보존하고, 명시적 빈 녹음 배열에서는 양면의 항목 및 기존 재생 상태를 함께 정리한다. 기존 오류 문구는 플레이어가 있는 앞면으로 이동한다.
- 추가 회귀 테스트는 플레이어 위치·중복 없음·출처 이동·초점·고유 연결 대상·양면 정리 및 숨김을 확인한다. 기존 lifecycle 테스트도 재생면 이탈 정지로 기대 동작을 맞춘다. 해당 diff에서 계약/필드 누락이나 추가 보강이 필요한 회귀를 찾지 못했다.

## 검증 범위와 한계

이 검토는 공식 라이선스 원문, 기존 API와 완료 patch를 읽은 독립 코드 검토다. UI 담당의 프런트엔드 334개 통과 보고를 전달받았으며, 동일 검사를 중복 실행하지 않았다. 실제 브라우저·오디오 재생·물리 모바일 검사는 이번 독립 검토에서 실행하지 않았다. UI만 변경하므로 이 요청 때문에 Python 전체 검사를 추가할 근거는 찾지 못했다.
