# RG-301 말장난이 붙은 단일 조류 질문 분류 보완

작성일: 2026-10-08. 대상: NAS TEST. 사용자가 “곤줄박이에 대해서 설명 해줄레이요 구르트 아줌마 요구르트 주세요” 입력 시 분류하지 못한다고 신고했다.

## 배경·목표와 실제 원인

공개 NAS TEST의 수정 전 응답은 HTTP 200, `route_method=jev`, `disposition=clarify`였으며 “질문의 종류를 판단하지 못했습니다”라고 안내했다. 같은 문장을 실제 Jev API로 확인한 결과 `uncertain`, confidence 0.71, uncertain 확률 0.73/profile 0.27이었다. 이름 추출은 이미 `곤줄박이`로 정상 동작했다. 기존 uncertain 기준의 “서로 독립인 여러 요청/지원 밖/조류와 무관”이 뒤의 요구르트 요청을 별도 요청으로 보도록 정의되어 있었다. 엄격한 정규식에도 맞지 않아 Jev가 최종 판정을 담당했다.

목표는 한 가지 조류 정보 요청에 붙은 말장난·호칭·추임새·존댓말 오타를 부수 발화로 구분하고, 원래 소개·먹이·아종 등의 주제를 유지하는 것이다. 실제 복수 정보 요청·대상 모호함·지시 주입은 추가 확인 정책을 유지한다.

## 변경 전후·구현 파일

- `src/robingraph/api/jev_router.py`: `INTENT_INSTRUCTIONS`에 문장 전체를 읽되 인사·호칭·웃음·말장난·무의미한 운율·존댓말/띄어쓰기 오타는 부수 발화로 보도록 명시했다. 일반 소개와 먹이 예시, 조류 외 정보를 추가로 묻는 요청과 두 종 질문의 반례를 함께 제시했다. uncertain 설명도 “중심 요청”과 “실질적 정보 요청”을 기준으로 구체화했다.
- 원문을 자르거나 이름을 보정하지 않는다. 임계값·오류 재시도·uncertain 처리·임베딩 대체 조건·이름 해소·필터 검증은 변경하지 않았다. 불확실 결과를 일반 소개로 덮어쓰는 우회는 추가하지 않았다.
- `tests/test_jev_router.py`: 신고 원문이 그대로 Jev에 전달되고 해당 모델 판정 후 정확한 이름으로 조회되는지, 먹이/아종 이름 추출, 필터 충돌·uncertain·낮은 확신도 조회 방지를 검증했다. 필터 없는 “곤줄박이 말고 박새 설명해줘”에서 이름을 임의 선택하지 않는 경계도 확인했다.
- `docs/jev-intent-routing.md`: 부수 발화 구분과 검증 기록 링크를 추가했다. UI·DB 구조는 변경 대상이 아니다.

## 협업·독립 검토

주 담당이 실제 NAS/Jev 재현·수정·API 평가·테스트·배포·문서화를 담당했다. `progressive_review`는 읽기 전용으로 질문 파싱·이름 추출·의도 경계를 조사하고 회귀 반례를 추천했으며, 최종 diff 검토와 Jev 단위 16개를 독립 실행했다. 프롬프트 변경에 배포 차단 문제는 발견하지 않았다. 실행 모델 이름은 별도 증거가 없어 추정하지 않는다.

## 검증 범위·실제 결과

수정 후 신고 원문을 실제 Jev API로 호출해 `profile`, confidence 0.95, profile 확률 0.96, 실패 없음, 1.721초를 확인했다. 다시 별도 대상 평가 14문항을 실제 호출했다. 소개/먹이/아종/외관/서식에 붙은 부수 발화, 두 종 질문, 조류와 요구르트 효능의 복수 정보 요청, 지시 주입, 모호한 대상, 조류 없는 발화, 기존 분류/관찰/문헌 주제를 포함했다.

14문항 중 사전에 둔 라벨과 일치한 것은 **13개**다. 불일치 1개는 “곤줄박이 말고 박새 설명해줘”의 예상 `uncertain` 대비 실제 `profile`이다. 의미상 한 종의 소개 요청이므로 profile 자체를 모델 오분류로 단정하지 않는다. 현 이름 추출기가 이 대상 변경 문법을 지원하지 않아 필터 없는 API는 추가 확인한다. 이 정책 기대값 불일치를 감춰 14/14 정확도라고 기록하지 않는다. 신고 원문 및 말장난을 붙인 먹이·아종 질문은 각각 기대 주제로 분류됐다. 이 14개는 수동으로 작성한 대상 회귀 표본이며 독립 heldout·전체 분류 성능 평가가 아니다.

- 실제 제공자 호출: 수정 전 1회·수정 직후 신고 문장 1회·대상 평가 14회. 대상 평가 응답 크레딧 합계는 14다. 공개 NAS API 호출은 이 수와 별도로 실제 Jev를 사용할 수 있다. 제공자가 모델 버전을 응답하지 않아 요청 모델 `typesafe/jev-1.13`을 실제 실행 버전으로 가장하지 않는다.
- Jev 집중 단위: **16개 통과, 실패 0, 건너뛰기 0**. 마지막 필터 없는 대상 변경 경계 추가 후에도 재실행해 16개 통과했다. HTTP·핸들러를 모의한 계약 검증이며 제공자 의미 판정의 증거는 위 실제 호출이다.
- 전체 Python: 전용 테스트 DB와 임시 PostgreSQL schema 실행기로 **608개 통과, 실패 0, 건너뛰기 0, 36.769초**. 실제 PostgreSQL·Neo4j 통합, MLflow SDK·원본 자료 검증을 포함한다. 외부 공급자를 쓰는 단위 테스트는 모의이며 전체 실행이 608회의 실제 Jev 호출이라는 뜻은 아니다. 임시 schema는 제거됐다.
- 프런트엔드 코드는 바뀌지 않아 이번에 다시 실행하지 않았다. 이전 작업의 152개 통과 결과와 혼동하지 않는다.
- `graphify update .` AST 갱신 완료. 추출기/커뮤니티 갱신 경고는 테스트 실패가 아니다.

## 한계·후속 사항

모델 판정은 모든 종류의 오타·농담·새로운 입력에 대한 보장이 아니며 낮은 확신도는 계속 추가 확인한다. “말고”로 대상을 바꾸는 문법은 이름 추출기가 아직 지원하지 않는다. 독립 검토에서 이 문장에 명시적 이름 필터를 붙이면 기존 entity 없음→필터 대체 정책 때문에 필터의 종을 조회하는 별도 기존 한계를 확인했다. 이번 수정은 신고한 단일 조류 질문의 부수 발화 구분에 한정하며 그 문법·필터 정책을 변경하지 않았다. 따라서 “대상 변경 문장도 모든 필터 조합에서 보호된다”라고 주장하지 않는다. 다른 백로그는 진행하지 않았다.
