# 작업 ID 체계

- 도입일: 2026-10-09
- 기준 문서: Obsidian `Work/RobinGraph/RobinGraph 작업 백로그`의 "작업 ID 체계" 섹션. 이 문서는 코드 읽는 사람이
  옛 번호(`RG-005` 등)를 새 번호로 찾을 수 있게 같은 대응표를 저장소에 둔 것이다.

## 배경

작업이 늘면서 `RG-001`~`RG-017`이 등록 순서로만 붙어 있어 DB, 검색, UI, 데이터 작업이 섞여 보였다.
카테고리별로 번호를 나눠 어떤 영역의 작업인지 번호만으로 알 수 있게 한다.

## 규칙

작업 ID는 **첫 자리가 카테고리, 뒤 두 자리가 카테고리 안의 등록 순번**이다
(101, 102, … / 201, 202, …). 새 작업부터 이 체계를 쓴다. 다음 번호는 해당 카테고리의 마지막 번호 + 1이다.
한 작업이 여러 카테고리에 걸치면 가장 큰 변경이 일어나는 쪽으로 정하고 상세에 관련 카테고리를 적는다.

| 카테고리 | 범위 |
|---|---|
| 1xx DB·저장소 | 데이터베이스 구조·이관·저장소 분담 |
| 2xx 검색·RAG·그래프 질의 | 검색 경로, 순위, 그래프 탐색, 근거 구성 |
| 3xx 질문 의도·LLM | 의도 분류, 외부 모델 연동, 프롬프트 |
| 4xx 채팅 UI·카드 | 화면, 카드, 표시 문구, 상호작용 |
| 5xx 데이터·분류·이름 | 수집, 분류, 한국어 이름, 출처, 데이터 품질 |
| 6xx 관측·평가 | 로깅, 추적, 평가 세트, 품질 측정 |
| 7xx 배포·인프라 | NAS·Docker·CI·환경 설정 |
| 8xx 문서·개발환경 | 문서 체계, 개발 도구, 저장소 정리 |
| 9xx 기타·실험 | 위에 안 맞는 일회성·탐색 작업 |

## 기존 번호를 바꾸지 않은 이유

옛 번호는 이미 다음 위치에 박혀 있다(2026-10-09 저장소 검색: 73개 파일이 `RG-0xx`를 언급).

- 코드 주석: `src/robingraph/api/static/chat.js`, `styles.css` (`RG-005`, `RG-008`, `RG-009`, `RG-015`)
- 테스트: `tests/frontend/chat_ui.test.js`(`RG-005`, `RG005_LINEAGE`), `tests/test_mlflow_response_tags.py`(`RG-016`)
- 검증 문서 파일명과 에셋: `docs/verification/2026-10-05-RG003-*.md` 등, `docs/verification/assets/` 23개
- Obsidian 작업기록 파일명과 본문, 과거 git 커밋 메시지, MLflow 기록

개명하면 링크가 깨지고 과거 기록과 번호가 어긋난다. 그래서 파일명·코드·기존 기록은 그대로 두고
이 대응표로 연결한다. 옛 번호는 계속 유효하다.

## 하지 않은 것

- 코드 주석, 테스트 이름, 파일명, 과거 작업기록 본문의 번호 변경
- Obsidian 백로그 상세 섹션의 제목(`### RG-0xx — …`) 변경. 제목 앵커 링크가 많아 그대로 둔다.
- 7xx 이상 카테고리에 대한 소급 분류. 해당 작업이 생길 때 등록한다.
