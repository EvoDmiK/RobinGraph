# 작업 ID 체계

- 도입일: 2026-10-09
- 기준 문서: Obsidian `Work/RobinGraph/RobinGraph 작업 백로그`의 "작업 ID 체계" 섹션. 이 문서는 코드와 파일명에 남은
  옛 번호(`RG-005` 등)를 새 번호로 찾을 수 있게 같은 대응표를 저장소에 둔 것이다.

## 배경

작업이 늘면서 `RG-001`~`RG-017`이 등록 순서로만 붙어 있어 DB, 검색, UI, 데이터 작업이 섞여 보였다.
카테고리별로 번호를 나눠 어떤 영역의 작업인지 번호만으로 알 수 있게 한다.

## 규칙

작업 ID(접두사 `RG-`)는 **첫 자리가 카테고리, 뒤 두 자리가 카테고리 안의 등록 순번**이다
(101, 102, … / 201, 202, …). 새 작업부터 이 체계를 쓴다. 다음 번호는 해당 카테고리의 마지막 번호 + 1이다.
한 작업이 여러 카테고리에 걸치면 가장 큰 변경이 일어나는 쪽으로 정하고 상세에 관련 카테고리를 적는다.

| 카테고리 | 범위 |
|---|---|
| 1xx DB·저장소 | 데이터베이스 구조·이관·저장소 분담 |
| 2xx 검색·RAG·그래프 질의 | 검색 경로, 순위, 그래프 탐색, 근거 구성 |
| 3xx 질문 의도·LLM | 의도 분류, 외부 모델 연동, 프롬프트 |
| 4xx 채팅 UI·카드 | 화면, 카드, 표시 문구, 상호작용 |
| 5xx 데이터·분류·이름 | 수집, 분류, 한국어 이름, 출처, 데이터 품질 |
| 6xx 관측·평가 | 로깅, 추적, 평가 세트, 품질 측정 |
| 7xx 배포·인프라 | NAS·Docker·CI·환경 설정 |
| 8xx 문서·개발환경 | 문서 체계, 개발 도구, 저장소 정리 |
| 9xx 기타·실험 | 위에 안 맞는 일회성·탐색 작업 |

## 무엇을 바꾸고 무엇을 바꾸지 않았나

2026-10-09에 문서 본문의 옛 번호 표기를 새 번호로 바꿨다. 코드와 파일명은 바꾸지 않았다.

| 구분 | 처리 |
|---|---|
| 저장소 `docs/`·README의 본문(링크 텍스트 포함) | 새 번호로 치환(44개 파일, 116줄) |
| Obsidian `Work/RobinGraph` 노트 본문·제목·ToC | 새 번호로 치환(42개 파일). 위키링크의 대상 경로와 제목 앵커도 함께 맞춤 |
| 코드 주석, 테스트 이름·상수 | 그대로. 예: `chat.js`·`styles.css`의 `RG-015`, `chat_ui.test.js`의 `RG-005`·`RG005_LINEAGE`, `test_mlflow_response_tags.py`의 `RG-016` |
| 파일명 | 그대로. 예: `docs/verification/2026-10-05-RG003-*.md`, `2026-10-09-rg015-*.md`, Obsidian `작업기록/2026-10-09-RG015-*.md` |
| 백틱(`` ` ``)으로 감싼 표기, 코드 블록 | 그대로. 코드·명령·식별자를 인용한 것일 수 있어 건드리지 않음 |
| 과거 git 커밋 메시지, MLflow 기록, 배포 이미지 태그 | 그대로(바꿀 수 없음) |

그래서 파일명이나 코드에서 옛 번호를 만나면 위 대응표로 새 번호를 찾는다. 반대로 문서 본문의 새 번호
(예: `RG-405`)로 관련 파일을 찾으려면 같은 표의 옛 번호(`RG-015`)로 파일명을 검색한다.

## 치환 규칙과 검증

- `RG-0NN`, 하이픈 없는 `RG0NN`을 대응표대로 치환했다. 다른 글자·숫자가 이어지는 `RG015-…`(파일명)은 건드리지 않았다.
- 번호가 연속이 아니게 된 범위 표기는 풀어 썼다. `RG-005~RG-009`는 `RG-401~RG-404·RG-502`로,
  `RG-004~RG-009`는 `RG-501·RG-502·RG-401~RG-404`로, `RG-014~RG-016`은 `RG-202·RG-405·RG-602`로,
  `RG-013~RG-015`는 `RG-301·RG-202·RG-405`로 바꿨다.
- 이 문서와 Obsidian 백로그의 대응표·변경 이력은 옛 번호를 그대로 남겨 두었다.
- 검증: Obsidian은 치환 전후 `Work/RobinGraph` 위키링크 326개의 파일·제목 앵커 해석을 비교해 모두 해석됨(깨진 링크 0)을
  확인했다. 저장소는 변경된 44개 파일의 상대 경로 마크다운 링크가 모두 존재함을 확인했다.
  코드·테스트는 바꾸지 않았으므로 테스트는 다시 실행하지 않았다.
- 한계: 의미까지 자동 검토하지는 않았다. 과거 기록 중 "RG-004~RG-009는 번호 순서상 …"처럼 옛 번호의
  순서에 의미가 있던 문장은 새 번호로 읽으면 어색할 수 있다.
