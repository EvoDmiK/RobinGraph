# RG-003 — 생태 관계 탐색

같은 속·과 탐색에 더해, 설명창에서 **같은 서식 환경·먹이 생태의 새 살펴보기**를 누르면 같은 생태 범주를 공유하는 종을 탐색한다. 후보의 **비교하기**는 별도 답변 말풍선에 두 종의 설명·카드와 출처를 준비한다.

이번 범위는 `habitat`(서식 환경)와 `trophic_niche`(먹이 생태)의 **같은 자료·같은 릴리스·같은 원문 분류값**이다. 현재 두 항목은 기존 n8n으로 적재한 AVONET에서 제공된다. 동일한 범주는 계통적 근연성, 실제 공존, 포식 관계를 뜻하지 않는다. 새 수집 워크플로나 추측한 먹이사슬을 추가하지 않는다.

## 조회와 출처

`GET /v1/taxa/ecological-related?name=청둥오리`는 종을 활성 분류판에서 해석하고, 허용된 원래 종의 형질을 기준으로 Neo4j에서 후보를 조회한다.

조회 경로는 `Taxon ← ASSERTS_ABOUT — TraitClaim — SUPPORTED_BY → EvidenceUnit`이다. 원래 종과 후보의 형질 노드는 각각 존재하며, 동일한 분류값을 비교해 관계를 도출한다. 영구적인 새 관계를 추측해 저장하지 않는다.

- PostgreSQL에서 활성화된 형질 자료만 사용하고, 개념집합·분류판이 현재 종의 분류판과 일치하는지 확인한다.
- 두 종 모두 허용된 `Taxon:BirdTaxon`, `species`, 동일 개념집합·분류 릴리스에 속해야 한다. GBIF 외부 분류군이나 아종의 부모 형질을 후보로 섞지 않는다.
- 두 형질 모두 허용 상태이며 `inferred=false`, 같은 `trait_name`, `dataset_id`, `source_release`, `value_text`여야 한다.
- 양쪽 증거 모두 허용 상태이고 각 형질의 자료 ID·원본 행 ID와 일치해야 한다. 현재 수집기는 증거에 `source_release`를 쓰지 않으므로 릴리스 검사는 형질 노드에서 수행한다.
- 검토된 범주만 한국어로 표시하며, 대상 범주와 각 후보의 출처·자료 버전·라이선스를 토글로 제공한다.
- 기존 한국어 이름과 IOC 참고 이름을 우선하고, 나머지 활성 종은 한국어 번역명으로 표시한다. 번역명은 구분하며 학명·영명은 보존한다. [표시명 정책](korean-display-names.md)을 따른다.
- 각 범주에서 종을 중복 제거하고 4개를 조회해 최대 3개를 표시한다. 추가 후보가 있으면 일부만 표시했음을 안내한다.

범주별 결과는 `relation`, `value`, `display`, 대상 `source`, 후보 `items`와 각 후보 `evidence`, `has_more`를 포함한다. 형질·출처가 없으면 빈 목록을 안내한다. 조회 실패는 재시도할 수 있으며, 후보 프로필의 분류판·ID가 바뀌거나 대화가 지워지면 늦은 결과를 표시하지 않는다.

RG-004~RG-009는 독립 작업이다. 이 문서는 RG-003의 생태 조회 부분을 설명한다. 전체 요구는 자연어 질문별 직접 답변이며 [질문 처리 정책](species-questions.md)과 해당 검증 기록을 따른다.

## 자연어 질문 연결

탐색 버튼은 보조 경로이며 `왜가리와 먹이가 비슷한 새는?`처럼 질문하면 해당 범주의 후보·출처를 바로 조회한다. 일반 `비슷한 종` 질문은 별도의 분류·생태 가중치 점수로 TOP-3를 제공한다. 이 범주별 목록은 기존 이름순에서 일부 3종을 보여주며 유사도 순위로 해석하지 않는다. [자연어 질문 정책](species-questions.md)을 따른다.
